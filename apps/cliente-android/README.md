# FLETYA Cliente · Piloto 0.1.0

Independent Android client app (`app.fletya.client`, min API 26, target/compile 36) using the existing public Supabase Auth/PostgREST and Routes endpoints. It can coexist with the driver app; each package encrypts its own session in Android Keystore and signs out with local scope. It accepts only database-validated `client` profiles. No service credentials, driver foreground services, Firebase configuration or background location are included.

The pilot supports existing-account login, profile name, addresses or map-point pickup/delivery, one-shot foreground current location, real route distance, quote review/confirmation, client-owned request creation, cancellation only while requested/unassigned, active service restoration, assigned driver identity and server-time-referenced GPS, and paginated history. Bundled Leaflet 1.9.4 has no native JS bridge; remote resources are restricted to HTTPS OSM tiles, with attribution. Polling retains draft inputs and existing map zoom; completed/released assignments remove the previous driver's point. Late responses are scoped to screen, session, request and current job.

Pricing intentionally matches the current web pilot: base 120 MXN, 35/45/65 per km for pickup/camioneta/camion, vehicle supplements 0/100/300, and 180 per helper (0–2). Service category currently does not change that tariff. Quotes expire after ten minutes and require explicit confirmation. A request UUID is reused on an in-process retry after an uncertain insert response. RLS and existing database guards remain authoritative for ownership and transitions; this change does not add server-authoritative pricing or a global one-active-request uniqueness constraint. Production payment collection is not implemented.

Registration/password recovery use the existing web flow for now. Map tiles, route calculation and tracking need internet; failed refreshes do not claim fresh GPS. Client location is requested only on the user's button press and stopped on backgrounding, timeout, success or navigation. Production `piloto` and isolated `pruebas` builds have separate package IDs and backend configuration.

Build: JDK 17, Gradle 8.13, Android SDK 36/build tools 35.0.0. Run `gradle --no-daemon testPruebasDebugUnitTest lintPruebasDebug assemblePruebasDebug assemblePilotoDebug`. The dedicated GitHub workflow builds both environments and exports tests/lint/APKs. Pilot builds use temporary debug signing and are not store releases; future persistent release signing remains necessary.

Device acceptance still needed: same-phone client+driver independent sessions; quote against web; map pick/current location; create → driver push → accept → client identity/GPS; pickup/completion/history; cancellation/acceptance conflict; denied permissions/offline behavior. Existing driver locked-screen push acceptance remains a separate deferred test.
